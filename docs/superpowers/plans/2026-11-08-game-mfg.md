# 游戏 1–6 倍补帧 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 在现有中文 NR 启动器中加入可撤回的游戏 1×–6× 补帧选择。

**Architecture:** 固定 Aurora 原生 SL 覆盖后端，通过独立 winmm.dll 与现有 NR 共存。补帧包校验、安装记录、支持检测及 UI 分离；取消操作合并两类记录。

**Tech Stack:** C# 5 / .NET Framework 4.x / WinForms，Windows 自带 tar 解包固定 7z；无需运行上游安装器。

**Spec:** ../specs/2026-11-08-game-mfg-design.md

## Global Constraints

- 主界面保持两个按钮；本轮只加游戏补帧；默认 1×=关闭。
- 保留游戏官方 DLL、已有 NR 参数和第三方文件；检测到冲突/反作弊/未知输入路径时停止覆盖。
- 上游原始包固定长度、哈希、来源、许可；不执行 setup/OptiPatcher/runtime_sync。
- 请求倍率与实际效果分开；不支持时不得静默降级，不把 NR 层数当补帧。
- 用户已委托直接实施与技术选择；无需再做方案审批。原程序在验证完成前保持可用。

## Review Focus

- 修改/伪造的所有权记录不能授权删除未知文件；路径穿越、链接、重复条目全部拒绝。
- 旧游戏 SL 版本、不同 DLSSG、未导入 winmm 不应显示补帧成功。
- 配置自动保存后改倍率仍保留用户无关偏好；撤回保留改动文件。
- FG 与 NR 共存，部分安装失败、游戏仍运行时不破坏另一套组件。
- 日志跨会话/初始化/重复帧不能作为当前完整 MFG 成功证据。
